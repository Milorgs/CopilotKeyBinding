# Copilot Key Binding 1.0

Maps the Copilot key to Codex on Windows x64. Native Win32 C; no .NET or AutoHotkey required.

## Features

- Captures `Win + Shift + F23` and opens Codex on key release.
- Event-driven, with no polling. App launch runs after the keyboard hook returns.
- Single instance; holding the key does not repeatedly launch the app.
- Runs without a persistent window or tray icon.
- Logs startup and errors, not ordinary keys or typed text.

## Use

1. Install Codex on Windows x64.
2. Download `CopilotKey.exe` from the [1.0 release](https://github.com/Milorgs/CopilotKeyBinding/releases/tag/v1.0) and keep it in a permanent folder.
3. Run it and press the Copilot key.

The keyboard must send `Win + Shift + F23`. The packaged app ID is `OpenAI.Codex_2p2nqsd0c76g0!App`. If it changes, update the source target and rebuild.

To run at sign-in, press `Win + R`, open `shell:startup`, and add a shortcut to the EXE. To stop mapping, end `CopilotKey.exe` in Task Manager and remove the startup shortcut if present.

For launch diagnostics, run `CopilotKey.exe --check`. Success means the launch request was sent; check whether Codex actually opened. `status.log` in the executable directory records `READY_NATIVE`, `HOOK_FAILED_NATIVE`, or `LAUNCH_ERROR_NATIVE`.

## Build and resource use

From the 1.0 source checkout, install MinGW-w64 GCC and run:

```powershell
.\build.ps1
# If GCC is not on PATH:
.\build.ps1 -Compiler 'C:\mingw64\bin\gcc.exe'
```

Output: `dist/CopilotKey.exe`, with a SHA-256 checksum printed by the build script. Runtime dependencies are Windows system libraries only.

On one Windows PC, working-set memory after opening Codex was about 5.5 MB and private memory about 0.87 MB, compared with about 35 MB for the earlier .NET version. No CPU-time increase was measured during a three-second idle sample. Results vary by device.

This is an independent utility, not an OpenAI or Microsoft product.

# 中文说明：1.0

将 Windows 电脑的 Copilot 实体键映射为打开 Codex。使用原生 Win32 C 实现，无需 .NET 或 AutoHotkey。

## 功能

- 拦截 `Win + Shift + F23`，松开时打开 Codex。
- 事件驱动，无定时轮询；应用启动在键盘钩子返回后执行。
- 单实例运行，长按不会反复启动。
- 无常驻窗口和托盘图标。
- 日志只记录程序启动和错误，不记录普通按键或输入文字。

## 使用

1. 在 Windows x64 上安装 Codex。
2. 下载发布版本中的 `CopilotKey.exe`，放到一个固定目录。
3. 双击运行，再按 Copilot 键。

程序面向发送 `Win + Shift + F23` 的 Copilot 键。其他键盘信号不在当前版本支持范围内。
默认打开 Microsoft Store 应用标识 `OpenAI.Codex_2p2nqsd0c76g0!App`。
如果该标识在应用更新后变化，需要修改源码里的 `target` 并重新构建。

### 登录后自动运行

按 `Win + R`，输入 `shell:startup`，把 `CopilotKey.exe` 的快捷方式放入打开的文件夹。

### 停用

在任务管理器中结束 `CopilotKey.exe`；如已设为自动运行，同时删除启动文件夹里的快捷方式。

### 排查启动问题

运行 `CopilotKey.exe --check` 可以直接请求打开 Codex，而不安装键盘钩子。
此命令成功只表示启动请求已发出；仍需确认 Codex 窗口是否出现。
运行目录里的 `status.log` 会记录 `READY_NATIVE`、`HOOK_FAILED_NATIVE` 或 `LAUNCH_ERROR_NATIVE`。

## 构建

Windows 上安装 MinGW-w64 GCC，然后在 PowerShell 中执行：

```powershell
.\build.ps1
# GCC 不在 PATH 时：
.\build.ps1 -Compiler 'D:\Program Files\mingw64\bin\gcc.exe'
```

输出为 `dist/CopilotKey.exe`，构建脚本同时输出 SHA-256。

## 占用

在开发者的一台 Windows 电脑上，启动 Codex 后的工作集约 5.5 MB，私有内存约 0.87 MB。
原 .NET/WinForms 版本工作集约 35 MB。空闲 3 秒观察期内没有测到 CPU 时间增加。
这些是单机测量值，不保证其他设备占用相同。
